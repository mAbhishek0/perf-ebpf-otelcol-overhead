PLATFORM L (LAPTOP) - HOW TO RUN THE BENCHMARKS
================================================
Status (2026-11-07): one-time setup, unit tests, nginx pilot, smoke cell,
the full nginx x perf matrix (8 cells) and stall diagnostic runs 1-3 are DONE.
Run 3 found the ~1 s stall: a timer bug in wrk2's event loop (ae.c).

NEXT: stall diagnostic run 4 = rebuild wrk2 with the fix, then 5 untraced
runs (about 15 min). The rebuild replaces /usr/local/bin/wrk2.

    git pull
    sudo bash install_build.sh
    sudo bash diag_stall.sh --variants base

install_build.sh must print "ae.c patched". If it stops with "ae.c timeout
clamp not found", paste its output in chat instead of running the diagnostic.
The report is in nginx-wrk2/diag/<time>/report.txt.
Then push: git add -A && git commit -m "results: stall diagnostic run 4" && git pull --rebase && git push

Everything below runs from the cloned folder:

    cd ~/Downloads/perf-ebpf-otelcol-overhead


EVERY RUN, THE SAME FOUR STEPS
------------------------------
1. Get the latest scripts (never while a run is going):

       git pull

2. Start the run (the command for the current step is given in chat), e.g.

       sudo bash nginx-wrk2/perf/scripts/run.sh

   What happens, all automatic:
   - It lists the services it will stop and apps it will close, waits 10 s
     (Ctrl+C cancels). Browsers/Telegram are closed and NOT reopened; save
     your work first.
   - The desktop stops (black screen is normal). It waits for the CPU to cool
     below 55 C, sets SMT off, boost off, clock 2.9 GHz, platform profile
     performance, fans at full speed, then runs.
   - At the end, or on any failure, it restores everything and the desktop
     comes back. If it comes back within minutes, it failed.

3. Watch it (optional): Ctrl+Alt+F3, log in, then

       L=$(ls -t logs/bench-*.log | head -n 1)
       grep -E 'cell .* ok|drift|WARN|FAIL' "$L"     # one "ok" per finished cell
       tail -n 5 "$L"
       exit

   Watching does not affect the measurements.

4. When the desktop is back, push the results (finished or failed):

       git add -A && git commit -m "results: <what ran>" && git pull --rebase && git push

   Then say "done" in chat.


IF SOMETHING GOES WRONG
-----------------------
Stop a run cleanly (still reverts the host and restores the desktop):

    sudo systemctl stop bench-nginx          (bench-pilot / bench-diag)

After a crash or power loss:

    sudo bash revert.sh

Quick look at why it stopped:

    tail -n 25 "$(ls -t logs/bench-*.log | head -n 1)"
    ls -t logs/crash_*.txt | head -n 1 | xargs -r sed -n '1,8p'

A rerun resumes: finished cells are skipped, a crashed cell restarts.

If "git pull --rebase" refuses because of file permissions:

    git rebase --abort; sudo chown -R ab:ab . ; git pull --rebase && git push

Full command trace for debugging only (adds load; never for reported data):

    sudo BENCH_TRACE=1 bash <command>


NOTES
-----
- Ubuntu's tail needs "-n 25", not "-25".
- Plain git pull/push works here; sync.sh (token in .sync.env) is the
  alternative if git asks for a password.
- Unit tests (no root, changes nothing): bash common/tests/run_tests.sh
